# 북마크와 저장 폴더

미사모에서 추출한 구현 지침이다. 다른 사이트에서도 사용할 수 있으며 대상의 기술 스택·데이터 계층·브랜드·사용자 요구를 우선한다.

## 구현 순서

1. 콘텐츠 ID 집합으로 저장 여부를 관리하고 원문 데이터와 분리한다. 같은 글이 여러 화면에 나타나면 한 상태 변경으로 모든 버튼을 갱신한다.

2. 기존 로그인/DB가 있으면 계정별 저장 구조를 우선 사용한다. localStorage 시제품이면 기존 초안·글·댓글 필드를 유지하면서 bookmarks와 folder 데이터를 추가한다.

3. 쓰기 성공 뒤 UI를 확정하거나 실패 시 optimistic 상태를 되돌린다. 저장 공간 부족·읽기 손상·권한 차단을 조용히 성공 처리하지 않는다.

4. 폴더 이름 검증과 중복 처리, 저장한 글만 폴더에 배정하는 규칙을 둔다. 저장 해제 시 해당 배정도 제거한다. 삭제된 원문이나 없는 ID는 안전한 안내로 표시한다.

5. 저장 목록·분류·폴더별 개수는 실제 상태에서 계산한다. 여러 탭은 storage 이벤트나 기존 데이터 계층으로 동기화하며 직접 만든 탭 이벤트와 타 탭 이벤트의 차이를 확인한다.

## 검증

모든 화면에서 토글 상태 일치, 새로고침, 다른 탭, 폴더 배정·저장 해제, 같은 이름, 실패 시 원복, 빈 목록을 검증한다.
