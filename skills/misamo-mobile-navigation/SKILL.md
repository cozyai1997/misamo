# 모바일 메뉴와 스와이프

미사모에서 추출한 구현 지침이다. 다른 사이트에서도 사용할 수 있으며 대상의 기술 스택·데이터 계층·브랜드·사용자 요구를 우선한다.

## 구현 순서

1. 메뉴의 DOM 또는 공통 route 정의에서 순서를 가져온다. 스와이프용으로 다른 배열을 하드코딩해 탭 순서와 어긋나게 하지 않는다. 탭과 스와이프는 같은 라우트 핸들러를 호출한다.

2. 한 손가락의 충분히 큰 수평 이동만 페이지 전환으로 판정한다. 세로 이동이 먼저 확정되면 취소하고 다중 터치·touchcancel·중간 route 변경도 무효화한다.

3. 에디터, 입력, 선택 중인 텍스트, 영상/슬라이더, 미디어 캐러셀, 가로 스크롤 영역은 자체 제스처를 우선한다. 모달·전체화면·글 상세 화면은 제품 요구가 없으면 탭 전환에서 제외한다.

4. 화면 가장자리의 OS 뒤로 가기를 보호하고 첫/마지막 메뉴를 넘어갈 때 임의 순환시키지 않는다. 스와이프 뒤 의도치 않은 클릭만 짧게 억제하며 일반 탭을 막지 않는다.

5. 하단 메뉴 safe area, 가상 키보드, 고정 도구와의 겹침을 확인한다. 데스크톱 메뉴와 모바일 중복 바로가기 제거는 화면별 요구를 따로 적용한다.

## 검증

탭과 스와이프의 동일 목적지, 세로/대각/짧은 움직임, 화면 끝, 다중 터치, 취소, 텍스트 선택, 사진 넘기기, 글 작성, 키보드 열린 상태를 확인한다. 데스크톱 크기 변경은 실기기 터치 검증을 대신하지 않는다.

## 구현 참고
